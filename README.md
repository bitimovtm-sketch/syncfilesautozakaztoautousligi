# Bitrix24 Deal Files Sync

Передаёт файлы из 5 полей сделки с портала 1 (`autozakaz.bitrix24.ru`) на портал 2 (`autouslugi25.bitrix24.ru`). Поиск сделки на портале 2 — по полю «Номер кузова».

## Логика

Для каждого из 5 файловых полей:
- На портале 1 поле пустое → портал 2 не трогаем.
- На портале 1 в поле есть файлы → содержимое поля на портале 2 полностью заменяется тем, что лежит на портале 1.

Если сделка на портале 2 с таким VIN не найдена — синхронизация пропускается.
Если VIN на портале 1 пуст — синхронизация пропускается.

## Деплой

### 1. Создать входящие вебхуки в обоих порталах

В каждом портале: **Настройки → Разработчикам → Другое → Входящий вебхук**.
Права: `crm` (минимально нужно для чтения/записи сделок и файлов).
Скопировать URL вида `https://<portal>.bitrix24.ru/rest/<USER_ID>/<TOKEN>/`.

### 2. Залить в GitHub

```bash
git init
git add .
git commit -m "init"
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

### 3. Развернуть на Railway

1. **New Project → Deploy from GitHub repo → выбрать репозиторий.**
2. **Variables**:
   - `PORTAL_1_WEBHOOK` = `https://autozakaz.bitrix24.ru/rest/.../.../`
   - `PORTAL_2_WEBHOOK` = `https://autouslugi25.bitrix24.ru/rest/.../.../`
3. **Settings → Networking → Generate Domain** → получаем `https://<...>.up.railway.app`.

### 4. Настроить робота на портале 1

CRM → Сделки → выбрать воронку → **Роботы и триггеры**.
На стадии (или нескольких), где могут изменяться файлы, добавить робота:

- Тип: **«Запросить URL»** (или похожий — главное, чтобы делал HTTP-запрос).
- Метод: `POST`.
- URL: `https://<...>.up.railway.app/sync?deal_id={=Document:ID}`

Можно поставить робота на каждый этап воронки — он лёгкий, просто отправляет ID.

## Проверка

После сохранения робота — открыть сделку, добавить файл, сохранить. В Railway → **Deployments → Logs** должны появиться строки вида:

```
=== sync start P1 deal=12345 ===
VIN='WBA...'
matched portal 2 deal id=678
Downloading file id=... from portal 1
updating portal 2, fields: ['ufCrm_1781046413', ...]
=== sync OK: P1 deal 12345 -> P2 deal 678 ===
```

## Тонкости

- **Ручные файлы на портале 2**: если в одно из 5 синхронизируемых полей загружен файл прямо на портале 2, и в этом же поле на портале 1 есть файлы — ручной файл сотрётся при следующей синхронизации. Это поведение «полная замена непустых полей».
- **Гонки**: если робот стреляет несколько раз подряд (быстрое добавление нескольких файлов в сделку), запускается несколько параллельных синков. Последний выигрывает, состояние может «дрожать» секунду. Для текущей задачи это нормально.
- **Безопасность**: эндпоинт `/sync` открыт. URL Railway случайный, но если хочется усилить — добавить проверку секретного query-параметра в роботе.
- **Поля и коды захардкожены** в `main.py` (`VIN_P1`, `VIN_P2`, `FILE_FIELDS`). Если коды поменяются — править словарь.
